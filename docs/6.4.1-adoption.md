## Evidence scope and limitations

Offline real Shell/Git fixtures cover workspace identity/legacy collision safety,
invalid/reversed/nonancestor/empty review ranges, zero-net-diff real commits,
Windows paths with spaces and linked worktrees, Native silent success, failure
retention, no-commit completion, command quoting, unchanged resume and stale
untracked/plan/log proof. Static dispatch contracts protect instruction boundaries;
they are not behavioral validation. External evidence records the exact commands,
outputs, source content hashes and materialized runtime file map.

Native evidence is append-only in `progress.md`; `plan-path` stores ownership.
A completion binds plan bytes, Git HEAD/index/diff, tracked and nonignored untracked
file content, and its log. Verification commands must not mutate that checkout.
Later tasks can make earlier evidence historical; stale evidence is not permission
to rerun a finished task. Reconcile changed scope explicitly, preserving records.
Ignored dependencies, external environment, and concurrent edits are not proven
unchanged; simultaneous executions of the same plan are unsupported. Existing
legacy completion lines without Native proof require reconciliation, not replay.
Absolute canonical identity is checkout-specific; copied ledgers are not portable.
Scratch remains in the documented self-ignoring working-tree location, not `.git`.

The nine manifest values are `6.4.1`; this document and release notes mark its
development-candidate status. No installed marketplace or external pin is updated.
The tested uncommitted snapshot retains its file/content identity separately from
the later repository commit; documentation updated for this push is not part of
the tested runtime. Published 6.3.6 baseline identity stays separate.

In the bounded Astra Low comparison, both versions passed all five Golden v3
cases and the inline task-evidence case. The recovery case failed its original
checker on both sides: the prompt did not specify the required log-path key, and
the checker missed redirected failure output. A separate corrected checker
accepted the saved artifacts offline, including the candidate helper evidence.
Original failures remain unchanged; there were no replacement live runs.

The resulting disposition is ready for human review with the corrected recovery
contract. The common-success tasks showed 11.19% higher wall time and 16.43% more
total tokens, below the predeclared 25% warning threshold but not an efficiency
benefit. This single-model, single-round evidence does not establish universal
no-regression, reliability, or suitability for other models. Further evaluation
is expected before any marketplace promotion.
