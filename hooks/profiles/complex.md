# Capability Profile: complex

Use the same shared core with more verification time for difficult boundaries,
not broader authority. Preserve the parent workflow, existing approval, and tool
permissions. Keep named contracts for the affected interfaces and a short risk
ledger: risk, evidence, mitigation or unknown, and the proof that closes it.
Use these to prioritize work, not to inventory the entire repository.

Keep one task and its test evidence in focus. Retain concise context summaries
and fetch missing excerpts instead of repeated full reads. Expand verification
only for a named contract or evidenced integration risk within authorization.
Allow one risk-led review when authorized by the user or selected workflow;
follow that workflow's required review process without adding a parallel cycle.
No autonomous unbounded review loops. Resolve concrete findings within scope,
record unresolved limits, and stop at the agreed finish condition or a blocked
evidence boundary. Additional time permits stronger relevant proof, not
speculative polish or tools after the truthful final.
